# Assumptions

1. One currency, 2 decimal places. Amounts are stored as `NUMERIC(18,2)` and handled as `Decimal`. Amounts with more than 2 decimals are rejected instead of rounded.
2. Money is returned as a string (`"100.50"`) so clients don't lose precision. Requests can send a number or a string.
3. IDs are UUIDs generated by the server. An unknown but valid UUID returns 404, an invalid one returns 422.
4. Insufficient balance returns 400 `INSUFFICIENT_BALANCE`. I kept 422 for malformed input only and used 400 for business rule failures.
5. A duplicate `reference_id` on the same account returns 409 with the existing transaction in `error.details.existing_transaction`. This applies even if the amount or type is different.
6. Rejected transactions are not stored, so the same `reference_id` can be used again later.
7. Sending `balance`, `id`, `created_at` or any unknown field returns 422 instead of being ignored.
8. `name` is required, trimmed, 1-100 characters, and doesn't need to be unique.
9. `description` is optional, max 255 characters.
10. `reference_id` is required, trimmed, 1-100 characters and case-sensitive.
11. `type` must be `credit` or `debit` (lowercase).
12. Pagination: `page` defaults to 1, `limit` to 10, max 100 (configurable). Invalid values return 400 `INVALID_PAGINATION`. A page past the end returns an empty list with the correct totals, and `total_pages` is 0 when there are no transactions.
13. History is sorted newest first by `created_at`, with `id` as a tie-breaker. Timestamps are UTC.
14. No overdraft. The balance can go to 0 but not below (also a DB check constraint).
15. Transfers need two different existing accounts. The same `reference_id` is used on both the debit and credit side, and both are linked with a `transfer_id`. The transfer is rejected if either account already has that `reference_id`.
16. No authentication. In a real system the endpoints would need auth and accounts would belong to users.
17. Accounts can't be deleted or renamed through the API.
18. I added `GET /accounts/{id}` and `GET /health` as extra endpoints.
19. I used PostgreSQL because I needed transactions, row-level locking and check/unique constraints.
